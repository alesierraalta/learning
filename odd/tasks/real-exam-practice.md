# Exam from a real exam, with practical exercises

Objective: in exam mode, a practical exam gets practical exercises in every part and a practical mock; the learner can upload a real exam or document (PDF or photos) and the tutor builds the route and a mock with the same structure from it.
Milestone #10, issues #306-#310. Branch `feat/306-real-exam-practice` from `origin/main` @ d7c0396. Builds on exam mode (odd/tasks/exam-mode.md).

## Specs
S1 — "si se elige algo practico, el tutor debe generar ejercicios practicos" — decision L2: "En cada parte + simulacro". In a run with `exam.format = practical`, every part carries practical exercises of the chosen practice kind; the closing mock stays practical (existing `exam-mock`). The engine blocks a part that lacks them.
S2 — Each practical exercise has a statement, a deliverable and a solution. Contract: `practica/<partId>.json` = `{"exercises": [{"id": "<safe id>", "enunciado": "...", "entregable": "...", "solucion": "..."}]}`; at least `thresholds.exam.minPracticePerPart` (rules/deep.json, 2) per part; a code exercise `codigo/<id>/ejercicio.json` with `parte = <partId>` and a nonempty `enunciado` also counts (its tests are its solution). Check `exam-practice` at each part stage; `SKIP` outside practical exam runs. The part page and its mini-quiz show the statement and deliverable with an answer box, keep the answer, and reveal the solution only after the learner submits.
S3 — "debe existir la opcion de que si yo subo un examen o documento" — decision L2: PDF and photos/screenshots. Contract: `POST api/subir` with the raw file as body, `Content-Type` one of `application/pdf`, `image/png`, `image/jpeg`, `image/webp`, header `X-File-Name`; at most 20 MB and 5 files per topic request; stored under `<vault>/.subidas/<id>/<safe name>`; a PDF also gets `<safe name>.txt` with its extracted text (`pdftotext`; if the tool is missing the upload fails with an exact error, never silently). Response `{"id", "nombre", "tipo"}`. `api/aprender` accepts `fuentes: [<id>, ...]`; the first-turn prompt names each stored path (and the PDF text path), tells the tutor to read them, and to pass them to `learning_stage` init as `sources` (see S5, D1); the tutor never copies them itself.
S4 — "el tutor arme la ruta para prepararme para ese examen, como el modo examen pero partiendo de un examen real" — decision L2: "Todo": the tutor deduces format, evaluable syllabus and question types from the uploaded exam. In exam mode with at least one source, the studio offers "Que lo deduzca el tutor" as the format (`examen.formato = "deducir"`, only valid with `fuentes`); the prompt then asks the tutor to deduce the format (and practice kind) from the exam and pass it to `init`.
S5 — The closing mock mirrors the real exam's structure and difficulty. Contract (D1): adapter `learning_stage` init accepts `sources: [<absolute path under <root>/.subidas/>]` (1-5, each must exist and be contained there; a PDF's `.txt` sibling travels with it) and `examSource: <one of those paths>`; after validating everything and before calling the engine, the adapter copies each source into `<topic>/fuentes/<name>` and passes `--exam-source fuentes/<name of examSource>`. Engine: `init --exam-source <topic-relative path under fuentes/>` (only with `--exam`, only on init; the file must exist) records `state.exam.source`. With a source, `plan.json` `examen` adds `"fuente": "<same path>"` and `"estructura": [{"tipo": "<question kind>", "cantidad": <n >= 1>}]` (nonempty), checked by `exam-plan`; `exam-mock` then requires `cuestionario-final.json` questions to have, per `tipo`, exactly the declared `cantidad`. Difficulty is skill-side (references/examen.md). Runs without a source behave exactly as today.
