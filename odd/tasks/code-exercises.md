# Code exercises
Objective: graded programming exercises inside Learnings (HTML view, studio and shell), for any language, corrected by running the learner's code against tests in an isolated container, plus a tutor review in the chat.
Authorized by L1–L2; branch feat/code-exercises in worktree ~/documents/learning-code-exercises (the other study chat keeps working on feat/learning-studio). Push and merge stay the user's decision.

## Specs
S1 — "necesito que también incluyamos una sección o una forma de poder evaluar código. Porque ya tenemos para matemáticas y preguntas" — a code-exercise section next to the existing quizzes.
S2 — "que con el Gentle Shell o lo que sea, se pueda, no sé, hacer ejercicios de código. Y que se vayan corrigiendo bien" — exercises are solved and graded from the HTML view/studio and from the shell; grading is objective (the code is executed against tests), never an opinion only.
S3 — "para laboratorio 2, escribir mucho código" / "hacer evaluaciones basadas en el código y hacer ejercicios. que se puedan ir corrigiendo dentro de nuestro de nuestra aplicación" — every attempt is corrected inside the app and recorded.
S4 — "son varios, asi que debe adaptarse a cualquiera" — language-agnostic: a language is a configuration entry (container image, file name, compile and run commands); adding one needs no code change.

## Design
- Vault: `<topic>/codigo/<id>/ejercicio.json` = `{titulo, enunciado (markdown), lenguaje, plantilla?, parte?, limite_segundos?, tests: [{nombre, entrada, salida, oculto?}]}`. Submissions: `<topic>/codigo/<id>/entregas/<NNN>.json` (never overwritten).
- Grading is stdin/stdout, like online judges: the program reads `entrada` and must print `salida` (trailing whitespace and CRLF normalized). Works the same for every language.
- Runners: `integrations/pi/runners.json` maps `lenguaje` → `{image, file, compile?, run}`. Execution: one `docker run` per attempt, no network, memory/CPU/pids limits, read-only root, all capabilities dropped, non-root user, per-test timeout, output size limit, container killed on overall timeout.
- Hidden tests (`oculto`) never reach the page: only their name and pass/fail.
- Bridge: page `GET /<token>/<topic>/codigo/<id>`; `POST /<token>/api/code/run` (visible tests + free input, not recorded); `POST /<token>/submit` kind `code` (all tests, saved, delivered to the chat for the tutor review). The topic page lists the exercises.
- Shell: `learning code list|open|test|submit|setup` over the same runner module.

### T2 detail (bridge + view + studio)
Runner API already committed in `integrations/pi/coderun.ts` (2964310): `loadRunners`, `readExercise`, `publicExercise`, `forPage`, `runCode`, `sameOutput`, `CodeRunError`.
- New module `integrations/pi/codevault.ts` (shared by the bridge and the T3 CLI): `exerciseFile(topicDir, id)` (id passes `safeTopic`, contained via `resolveContained`); `listExercises(topicDir, runners)` → `[{id, titulo, lenguaje, parte?, entregas, mejor: "a/b"|null, error?}]` sorted by id (a malformed exercise is listed with `error`, never hides the others); `readSubmissions(exDir)` → summaries `[{numero, fecha, aprobados, total}]` + last code; `saveSubmission(exDir, record)` writes `entregas/NNN.json` (3-digit, next free number, exclusive create `wx`, never overwrites) with `{numero, fecha (ISO), lenguaje, codigo, nota?, compilacion, resultados (full, hidden included), aprobados, total}`.
- Bridge `BridgeOptions` gains `runnersFile?` (tests); runners are reloaded per request so editing runners.json applies live. A `CodeRunError` becomes HTTP 422 with its message.
- `GET /<token>/<topic>/codigo/<id>` → generic `page()` with `kind: "code"`: `{topic, exercise: publicExercise(...) + {id}, file: runner.file, submissions, lastCode, runUrl, topicBase, topicTitle}`. Hidden test input/output never reach the HTML.
- `POST /<token>/api/code/run` (same Origin/Host/JSON checks as submit; body keys exactly `topic, exercise, code, input?`): without `input` runs the visible tests; with `input` runs one free test `{nombre: "Entrada libre", entrada: input}` (no expected output, state `ejecutado`). Not recorded, not sent to the chat. Responds `forPage(result)`.
- `POST /<token>/submit` new kind `code` (keys `kind, topic, exercise, code, note?`): runs ALL tests, saves the submission, delivers one chat message `[Vista HTML · <topic> · código <id>]` with the saved path, score, compile status, one line per test (hidden ones included, with expected/obtained for failures), the code in a fenced block tagged with the language, the optional note quoted, and the instruction for the tutor to review it (correctness from the tests, approach, readability, typical mistakes) and inject the correction into the topic note as usual. Responds `{...forPage(result), saved, score}`.
- Topic page: `kind: "topic"` also carries `exercises` (from `listExercises`); a topic folder with `codigo/` but no `plan.json` still renders (parts empty). `listTopics` includes such folders and adds `exercises: [{id, titulo, lenguaje, mejor}]` to every `TopicSummary`.
- `learning_view` tool: `part` also accepts `codigo/<id>` (validated) and returns that page URL; update its description.
- View `integrations/pi/view/app.js` + `app.css`: topic page lists "Ejercicios de código" (title, language, best score); part page lists the exercises whose `parte` is that part; `kind: "code"` page = statement (markdown), language + file name, visible tests (input/expected in `<pre>`), count of hidden tests, monospace `<textarea>` editor (spellcheck off, Tab inserts 4 spaces, Ctrl/Cmd+Enter runs visible tests, draft autosaved in `localStorage` key `learning-code:<topic>:<id>`, initial text = draft, else last submitted code, else `plantilla`), buttons "Probar con las pruebas visibles", "Probar con mi entrada" (input textarea), "Entregar al tutor" (optional note), "Restaurar plantilla" (confirm); results panel: compile output, per test ✔ correcto / ✘ incorrecto / ⏱ tiempo / 💥 error / ▶ ejecutado with input, expected, obtained, errors for visible tests and only the state for hidden ones; submissions history `#N · a/b · fecha`. All UI copy in Spanish (project convention).
- Studio `studio/ui/studio.js`: the topic card/list shows its code exercises and opens them through the existing `api/view` path with `part=codigo/<id>`; touch the studio minimally (another chat works on it).
- Tests (`integrations/pi/bridge.test.mjs`, real Docker with `python:3.12-alpine`, skipped with a reason when missing): page hides hidden tests; run returns visible results only; free input; submit saves `entregas/001.json` then `002.json`, delivers the chat message (assert its header, score and code block), rejects foreign Origin and unknown keys; unsafe exercise id → 4xx; topic without plan but with `codigo/` lists it; `learning_view` with `codigo/<id>`. Existing tests stay green.
