# Pareto scope: ask, then teach only the vital 20%

Objective: before an explanation starts, ask the learner whether they want to learn with the Pareto rule; when they say yes, the explanation covers only the vital 20% of the content that produces 80% of the results, trimmed to the minimum that still allows understanding it, and it declares explicitly what is left out.
Authorized: L1. The three implementation decisions D1-D3 were taken by the agent from the existing repository contract and are revisable by the user. Branch `feat/pareto-scope` on top of `feat/learnings-name`. Push and merge stay the user's decision.

## Specs
S1 — "cuando te vaya a hacer una explicación te preguntes si quieres aprender con la ley de Pareto" — the decision is asked once, before teaching, in every explanation mode.
S2 — "solamente te explique el ochenta por ciento del con el veinte por ciento del contenido para el ochenta por los resultados" — the run carries a `scope`; `pareto` caps the plan to the vital few parts and requires each part to declare the capability it buys.
S3 — "con el contenido más recortado para entenderlo o sea para entender lo máximo con el mínimo esfuerzo" — Pareto mode declares what it drops, caps the parts and the words of each part, and the part states its vital slice under the heading `El 20% que rinde el 80%`.
S4 — Decision D3: measurement is never trimmed (answer keys, rigor, mini-quiz and vuelco stay complete); Pareto trims the explanation, not the proof that it was understood.

## Contract (shared by engine, adapter and skill)
- CLI: `learning init ... [--scope pareto|complete]` (default `complete`; `--scope` is accepted only by `init`). The engine records `state.scope`; every later command reads it from state. Old states without `scope` behave as `complete`.
- Engine report: `init` returns `evidence.scope`, every `status` report carries `scope`, and `status` adds a `scope` PASS check. `advance`/`validate` do not report it: they read it from state.
- `rules/deep.json` thresholds add `pareto`: `{"maxParts": 4, "minCriterioChars": 24, "heading": "El 20% que rinde el 80%", "maxWords": 1600}`.
- New deterministic check kinds: `pareto_plan` (preparation and planning, artifact `plan.json`, `receipt: false`) and `pareto_part` (explanation, artifact `explicaciones/Parte {index} - {slug}.md`). In `complete` scope both report `SKIP`, never a demand.
- `plan.json` in pareto scope adds `"pareto": {"criterio": "<why these are the vital 20%>", "descartado": ["<content deliberately left out>", ...]}`.
- Each plan part in pareto scope adds `"pareto": "<the capability this part buys towards the 80%>"`.
- New rubric `pareto-value` (stage `explanation`, kind `gate`, `when: "pareto"`): judges whether the part really delivers vital value and keeps what the plan declares out of scope out.
- Adapter: `learning_stage` `init` accepts `scope` and passes `--scope`; the report is returned unchanged.
- Skill `explicacion-interactiva`: Phase 0a asks mode + Pareto in one batch; `references/pareto.md` owns the selection procedure, what is cut, what is never cut, and the quick-note shape.
